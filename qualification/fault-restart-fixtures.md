# Batch 3: future native fault/restart fixture specification — NOT EXECUTABLE

This is a specification, **not** a fault injector. Do not add live callbacks, force a production destructive call, run `gameTestServer`, reuse `src/probe`, forge a ready provider, or launch a world. Every `fault_*` ID below is **blocked** while real production connected-set dispatch, genuine zero-mutation gate proof, exact artifact provenance, complete source+destination world backup and recovery, and human runtime authorization are absent. A saved journal or reversed VS teleport is not full-world recovery.

## Common retained per-attempt fixture (not created by this document)

On a future separately reviewed disposable attempt, use a fresh canonical UUID4 and separate disposable world UUID, nonblocking project `.tmp/spaceflight-runtime.lock`, immutable input/path+byte snapshot and original VS/JAR/Forge verification **before** any game mutation. Assign unique UUIDs per tier; never reuse a failed world. Set ≤230 s process timeout + ≤20 s owned cleanup; retain failures instead of deleting worlds. Collect pre/post authoritative snapshots with monotonic sequence, wall UTC, source+destination dimension IDs and full region bytes: block/BE/cargo/ForgeCaps/scheduled ticks and deadlines, meaningful unloaded claims, loaded FULL/pending-unload holders, actors including offline UUIDs and passenger/seat graph, ship IDs/poses/inertias/native-body handles/joints/listener ownership on the physics thread. Respect 64-member/128-FULL-chunk/128-actor/8 MiB-per-part/64 MiB-aggregate bounds; exceeding them **blocks** admission rather than truncating claims. Record explicit target occupancy and all four addon states before dispatch. Use durable **both-worlds** backup ID, raw region/actor/player hashes and a restore verification transcript. Retain exact pre-fault source, target and saved-backup bytes; after a fault never overwrite them to make a pass. `before_snapshot` and `after_snapshot` names are provenance pointers to retained bytes/logs, not proof by themselves.

A controlled injection must identify its actual source/game/physics thread, guarded one-shot trigger, frame nonce, member/ship/joint IDs, precise **before/after** operation sequence and fsync result. Fail closed on missing/ambiguous trigger (no inferred injection from server shutdown). Actual observed process exit, native ACKs, backup identity, post-fault quarantine and a cold-start reconciliation on the **same** frozen candidate must accompany every scenario. `failed` likewise requires executed authenticated observations; silence is `blocked`, not a success. There is currently no trustworthy producer or code path to satisfy any of this.

For every fault row, `fault_point` is the **exact** machine token listed in `scripts/qualification-evidence.py` (`FAULT_POINTS`); token aliases are invalid. A `passed` label with absent trigger, before/after snapshots, source+target/actor bytes, failed-world retention, observed process exit, cleanup and cold restart is **ambiguous fault injection** and must not be accepted. The batch-3 evidence validator intentionally returns `blocked` even if someone populates all fields: authentic native evidence is impossible from this author-only spec.
