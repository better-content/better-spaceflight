# Better Spaceflight source — feasibility stage

Java/Forge source for an isolated feasibility lab. This is an independent repository, not a fork of the main pack or VS. It contains a version-pinned adapter, a separate nonshipping diagnostic probe, and a **dormant** VS 2.4.11 compatibility substrate; survival gameplay is not implemented.

## Public source snapshot — not a release

This repository is a **new, history-free snapshot** of the current source tree, published to [`better-content/better-spaceflight`](https://github.com/better-content/better-spaceflight). The earlier private experimental repository and its history, including accidentally tracked compressed debug logs, were **not** copied here. Historical references below to unpublished code describe the original checkpoints; linked evidence and parent-workspace documents may exist only in the original local lab.

Public source availability is not a build, release, or gameplay acceptance: dynamic coast motion remains failing, the generated Forge mapping checksum still blocks trusted Gradle verification, and real-client, passenger, restart, and survival acceptance remain open. It does not authorize engineering continuation, runtime retries, JAR staging, or deployment. Original JARs and runtime evidence remain local.

## Dormant VS 2.4.11 compatibility substrate (unqualified)

`src/main/java/com/bettercontent/spaceflight/vs/compat/` contains a bounded joint-only fsynced journal, physics-boundary reservation protocol, detached VS joint DTO codec and pinned native-call Mixins. The shipping Mixin config is **default OFF**; only the deliberate JVM property `-Dbetter_spaceflight.experimental.vs2411_hooks=true` requests loading, and the plugin then verifies VS 2.4.11 metadata and exact original target class hashes before applying hooks. This opt-in is for future isolated review, **not** transfer authorization or a gameplay switch. There is no world-owner binding, startup reconciliation, production pilot/UI admission or destructive assembly-dispatch caller in this batch. Ordinary server behavior must remain unchanged without the opt-in. The original VS JAR is unchanged.

Terminal durability boundary: before the physics owner has verified successful release, cancellation, deadline or native failure re-quarantines every surviving body **in that same physics boundary**. The resulting `RELEASE_ACK` makes physical release irrevocable: late timeout/shutdown cannot re-freeze while a `RELEASED` marker may be committing outside the monitor. A confirmed fsync yields `RELEASED`, clears claims and publishes the terminal ACK together. An I/O throw after release is **not proof the marker failed** (atomic replace may already have succeeded): the owner hard-stops with `RELEASE_PERSIST_UNKNOWN`, keeps claims, and requires manual durable-record/world reconciliation; it does not assert successful completion or re-quarantine. A stopped pipeline that never wrote its terminal ACK likewise retains an incomplete `COMMITTED` journal, not an assertion of safe recovery. The joint journal is **not** a backup of shipyard chunks, block entities, scheduled ticks, cargo or passengers. Interrupted teleport cannot be called recoverable from these records alone; complete world-backup/recovery and controller wiring must be reviewed before dispatch. Unknown external/native constraints and listener-bearing addon craft fail preflight; no generic addon compatibility is claimed. Existing equal-layout rejection stays enabled (Twilight route unresolved), and the historical moving-ship coast `vx=10/dx=0` remains unqualified. No transformed Mixin, JNI physics, multiplayer, client, restart or world test has run for this substrate.

Batch-1 correction validation: the Gradle `test --dry-run` task graph succeeded, but an attempted focused Gradle unit run stopped **before tests** on generated mapped Forge JAR verification (pinned SHA-256 `57930057...`, generated `5156e660...`). Verification metadata and dependency locks were not relaxed. Separately, direct Java 17 `javac -proc:none --release 17` compiled the **new compatibility source only** against pinned original VS and existing cached libraries; **37/37 pure JUnit-API assertion methods** passed using an isolated direct runner, including physics-owner timeout/shutdown/partial-release fake-body behavior, exact original VS bytecode/metadata, default-off gating and actual fixed/distance-joint DTO round trips. That runner is **not** the Gradle/JUnit platform suite and does not validate transformed or native behavior. Full-main Gradle compilation remains blocked; no JAR task, runtime, world, deployment or publication was attempted for this change.

## Batch 2a: source-only space resources and pure travel policy

`src/main/resources/data/better_spaceflight/{dimension,dimension_type}/space.json` defines an empty flat `minecraft:the_void` space with no generated layers/features/structures, `min_y=-64`, `height=384`, and vanilla `minecraft:the_end` sky effects. It uses the same layout as the Overworld for the existing equal-section guard. Production **does not** include the old probe-only `vs_dimension_parameters/space.json`: that file deliberately set zero gravity and an extreme density threshold for a historical fixture, and is **not** normal flight behavior. No production gravity, propulsion, VS-physics parameters or sky renderer changed. Biome/type data prevent ordinary natural terrain/spawns; no claim is made about arbitrary modded spawns or observed gameplay.

`ServerTravelPolicy` is standalone pure server-game-tick logic, with **no registered server listener, native call, UI, transport, activation or player-accessible route**. Its four labeled **region definitions only** (not visible or spawned gates) occupy N/E/S/W at radius 1024, Y256 with activation sphere radius 64: Overworld, Wastelands, Twilight Forest, Abyssal. The surface allowlist is exactly those four IDs. An upward crossing of Y512 offers a nonautomatic confirmation for space; swept segment/sphere detection offers a gate confirmation from space. An offer is not movement. Nonces expire after 600 server **game** ticks (30 nominal seconds), are actor/assembly/source/destination bound, and are consumed only by the bound actor's confirmation attempt. Current authority, entire connected member set, destination enablement, transfer readiness and position are rechecked. Cooldown is 200 game ticks and leave-to-rearm is scoped to **all member ship IDs**, surviving pilot/root swaps; stale idle state is evicted only after cooldown and pending tokens end, and a first observation after eviction is a non-offering baseline. `stopOwner` and `invalidateActor` invalidate outstanding offers. Failures or absent/throwing live providers deny. The source defines no fake permissive provider: actual `PilotAuthority`, `AssemblySnapshot` and `TransferReadiness` have no production implementations or wiring.

Native transport remains unavailable: world lifecycle, durable full-world/cargo recovery and addon/physics compatibility are not solved by a policy confirmation. In particular the Twilight layout mismatch still fails the existing native equal-layout guard; readiness **must** reject a route that cannot safely transfer, even if its region is defined. New resources are **not deployed**; no gates are rendered or spawned. Batch-2a direct Java 17 compilation of the new travel plus compatibility sources succeeded; **17/17** pure policy/resource assertions and **54/54** combined JUnit-API direct-run assertions passed. These are source checks, **not** Gradle/JUnit-platform, transformed Mixin, native or world acceptance; the mapped Forge JAR verification mismatch still blocks Gradle. The historical probe files and tests remain separate and unchanged.

## Batch 2b: source-only owner, pilot and optional Eureka guards (no admission)

`ForgeVsServerOwner` registers one server-lifetime observer. It scans `better-spaceflight-joint-migration` under the actual world root **before** any potential bind; corrupted, pending or nonterminal joint journals block with path/nonce/phase diagnostics. A terminal joint journal is not a whole-world recovery certificate. Normal/default-off play gets no native binding. With explicit experimental opt-in, a synchronized idempotent verifier shared by both independent Mixin plugins uses Forge's loading ModFile archive path plus classloader resource bytes (not a guessed `jar:`/`union:` URL), rejects absent/altered original VS 2.4.11, and the binder still requires actual FQ/FN transformed accessor interfaces and a physics-hook heartbeat from **the same observed FQ.h Thread**. If the Forge loading list is unavailable at plugin phase, it fails closed; loader-stage behavior is NOT runtime-tested. No reservation request, policy `TransferReadiness` implementation, adapter call or transport entrypoint is wired. Server stop requests registry shutdown; an off-server-thread watcher waits boundedly for the exact previously alive native physics thread to reach TERMINATED and retries outstanding journal I/O before retiring claims. It cannot prove the asynchronous native resource-close coroutine completed; it never treats a flag or a null thread as proof. If the thread/journal does not settle, claims remain held and the owner reports a fault.

`SeatedVsPilotAuthority` is a real game-thread-only **selection** for a live `ShipMountingEntity` controller seat with exactly the controlling `ServerPlayer` passenger and an identical canonical loaded VS ship. It denies unknown/on-deck pilots. It compares loaded-ship ownership using VS's internal dimension string but exposes the Minecraft **ResourceLocation** ID to the pure travel policy. Selection is not a joint-component snapshot; only the physics boundary can verify full connected membership before any future dispatch.

Optional Eureka 1.6.3 Mixins are a separate **default-off** config, available only when exact original Eureka archive+classloader target bytes and pinned VS hooks pass. The exact helm `disassemble()` and `align()` entrypoints consult only registry immutable claimed-membership plus source/destination dimension and server identity (never the physics-owned native body map on the game thread); non-held helms keep ordinary behavior. Claims+snapshot become game-visible atomically before native suspension begins. After physical `RELEASE_ACK`, even if terminal fsync becomes unknown, admission claims remain but physics force, helm, static and joint mutation **seals end irrevocably**. Read-only `Eureka163ListenerEvidence` checks canonical attachment/ship/seated actor identity, anchors/align/disassembly and finite pending force buffers via pinned getters/private handles, without clearing normal engine buffers. **Native preflight STILL REJECTS ALL physics listeners**: no destination LoadedServerShip/seated-player rebind, full-world cargo recovery, setRemoved expected-mutation permit, or gameplay activation exists. ## Batch 3a: read-only affected-craft capture EVIDENCE (not recovery)

`ReviewOnlyCapture` has **no production caller**. This is **partial selected-capture evidence**, not the complete planned recovery/preflight functionality. Under an exact game-thread server, a `PREPARING` journal snapshot checked against the exact bound server-owner registry identity, same-layout source/destination, and one per-server capture lease, it validates all known active chunks of every connected member against an explicitly supplied, bounded set of **loaded FULL** shipyard chunks. It calls the real Forge/Minecraft `ChunkSerializer.write` once per chunk, rejects omitted/duplicate live block-entity records, retains full unmodified NBT including palettes, inventories, tick lists, PostProcessing, heightmaps, structures and ForgeCaps *when present*, and encodes with an 8 MiB per-part streaming limit. Every chunk carries a separate hashed capability-observation marker in the manifest (present/absent); either way a global status blocker records Forge's possible silent omission of failing providers. Forge `ChunkSerializer` can catch and omit failed capability serialization, so missing `ForgeCaps` is marked unqualified; the adapter does **not** call an arbitrary capability serializer twice to fabricate a pass. Known active chunks alone do **not** prove all pending-only loaded/unloaded shipyard chunks or external POI/light/tick data were included. The capture status always says chunk coverage unproven.

`LoadedActorCapture` uses actual loaded entity/player NBT serialization for a supplied candidate riding-root set, verifies the recursive nonplayer passenger UUID/order/count and separately saves every selected online `ServerPlayer` (vanilla may omit players from ordinary entity-region passenger NBT). It records exact candidate UUID/riding edges **and separate live XYZ/rotation/motion**, because mounted-entity NBT may encode vehicle position rather than the passenger's exact pose. Distinct selected actor objects with duplicate UUIDs refuse before serialization. It cannot prove that every on-deck, unloaded, offline or otherwise unobserved actor was selected; actor closure is always marked **unproven**. Unknown, noncanonical, disconnected or unserializable selected actors fail closed.

For exactly loaded canonical VS `ShipData` with **no live attachments** and no cached attachment JSON, `PinnedVsShipCapture` obtains the same `ServerShipDataConverter` and CBOR mapper configured in the original VS pipeline via narrowly typed pinned private fields. It performs one original `convertToDto`, accepting only normal upstream attachment-cache/tombstone housekeeping, bounded CBOR encode, bounded-depth detached V4 decode and byte-for-byte DTO re-encode. Original+Forge-mapped hashes for 16 codec/holder/DTO classes are pinned. This is **encoded per-ship data evidence**, not a proof of restoration. Nonempty/unreviewed/transient/failed attachment serializers, including the Eureka listener, remain unsupported; the native listener admission veto remains unchanged. No whole-pipeline snapshot is represented as a per-ship restore. If the exact accessors or mapper are inaccessible, capture refuses rather than substituting a lossy metadata projection.

The `CaptureEnvelope` binds a detached physical joint-record byte payload to world-root, nonce, source/destination, member IDs, capture game tick, part lengths/hashes and explicit per-component blocker status. Caps: **64 connected members, 128 unique loaded chunks, 128 selected actors, 8 MiB per part, 64 MiB aggregate**; excess refuses rather than truncates. A dedicated worker writes detached bytes using new files, per-file `force(true)`, atomic directory rename and directory fsync. The caller gets only a completion-stage view: mutating/cancelling its future mirror cannot end the actual I/O task or release the server lease. Game/physics threads never wait for this worker. The selected adapter verifies the exact server-owned registry, but the generic I/O writer **does not by itself authenticate the world-root/server relationship at submission**; that owner/world binding remains a prerequisite before any production caller is authorized. No restore command, semantic source recapture after asynchronous I/O, exact off-active-chunk coverage proof, unknown attachment/provider handoff, or destructive caller exists yet. `LastUpdate` and serialized relative tick delays require comparison-only normalization to absolute deadlines in a future reviewed protocol; raw bytes remain retained, and genuine powered cargo changes must invalidate stale captures. An aborted predispatch journal may still leave `PREPARING` on disk: never mark it `RELEASED` to fake a trip. Twilight's unequal-layout rejection remains unchanged. **This batch cannot authorize transfer, even for empty-attachment ships.**

The final direct full-main Java 17 compile against cached mapped dependencies (including the VS JAR's own Jackson 2.14 JarJar libraries) passed with four absent `Dist` metadata warnings; **86/86** pure JUnit-API assertions passed. These checks did not execute Forge/Minecraft, native physics, transformed Mixins, or actual serializers; the Gradle mapped-Forge SHA-256 verification mismatch still blocks a trusted build.

## Batch 3b: bounded source-only confirmation work (still NOT recovery qualification)

`CaptureEnvelopeWriter(MinecraftServer, ReservationRegistry)` checks the actual Forge server-owner registry before acquiring its lease and rechecks the bound world-root, complete detached physical joint journal, exact `PREPARING` snapshot and game-thread ownership at submission. Package-private generic construction exists only for pure concurrency fixtures. Only the real worker's post-fsync result (never a caller-mutated future mirror) can enable the nonblocking `durableCaptureReady` check. `ReviewOnlyCapture.revalidate` may then recapture on a strictly later game tick within 200 game ticks of the first snapshot; same-tick/older/unbounded captures refuse. There is no native handoff or readiness caller. `SemanticCaptureComparator` retains original bytes, compares all part keys and all actor/ship/Forge/tick-detail payloads exactly, and normalizes **only** root `LastUpdate` and the vanilla ScheduledTick `int t` relative delay into checked absolute deadlines in parsed comparison copies. Tick type, position, priority, list order/count, exact live trigger/sub-order, and meaningful cargo/BE changes invalidate. The pre-read live ScheduledTick inventory is cross-checked against every row of the **single** original chunk writer output for identity, trigger deadline, priority and count; missing or unknown serialized ticks refuse before envelope creation. It rejects malformed encodings, overflow and backward time. A changing powered craft still has no quiescence protocol; no single successful comparison promises future stability.

At capture and recapture, `LoadedShipyardChunkSelection` walks bounded actual server `ChunkMap` visible, updating and pending-unload holders, not every allocated ship-claim square, and rejects non-FULL/inaccessible/mismatched holders. Candidate set must exactly match all discovered connected-claim loaded chunks, including pending-only **loaded** chunks, plus the VS active set; no chunk is generated. Unloaded/on-disk meaningful claim state is **not proven**. `LoadedOnboardActorSelection` scans a bounded actual source `getAllEntities()` and online players, derives membership only from VS shipyard ownership, mounted-ship or active drag/contact identity, and rejects conflicting ownership, unknown addon mount providers, cross-ship riding roots and disconnects. The original VS `ShipMountingEntity` exact built-in pilot seat is allowed: its pinned class lacks the provider interface and the VS mounted fallback resolves the vehicle through loaded shipyard ownership. A separate hashed VS claim/mount/drag/contact topology part records root/vehicle identities and raw contact counters so topology changes invalidate recapture even when ordinary riding NBT looks unchanged. Offline players and unobserved/on-deck contact semantics remain outside this proof; status does **not** claim global actor closure. No AABB-only nearby-actor guessing or offline-player tracking service was added.

The one original `ChunkSerializer.write` call is bracketed by exact typed **read-only** Forge provider-field snapshots. Original server/Forge and mapped-development class hashes for LevelChunk, ChunkSerializer, CapabilityProvider, AsField and CapabilityDispatcher are pinned; inaccessible/unrecognized classes refuse. Validation distinguishes initialized no-provider, intact uninitialized lazy cached **NBT**, and initialized writers whose registered unique names exactly match the saved `ForgeCaps` keys; changed registration, missing/extra keys, failed original serialization or unknown lazy state refuses. This closes only the inspected top-level Forge capability *omission* path for selected FULL chunks, not arbitrary provider content fidelity, silently wrong BE serializer contents, pending/offline chunks, transformed-Mixin delivery or restored world state. The mapped Forge build checksum mismatch has NOT been waived, and bytecode-pinned development checks do not prove runtime accessibility.

All batch 3a evidence and constraints above remain historical; batch 3b narrows some previously unqualified selected-capture omissions but does **not** promote that partial checkpoint into completed recovery, powered/Eureka support, transfer or release. Direct full-main mapped Java 17 compile passes with four missing `Dist` metadata warnings; **98/98** isolated pure JUnit-API methods pass, including synthetic semantic deadline/meaningful-change, provider-omission and artifact-bytecode checks. No original Forge/Minecraft game-loop or transformed Mixin ran. Existing hooks stay default OFF; native listener veto, Twilight unequal-layout refusal and production gravity remain unchanged.

## Manual client/server transfer probe

The `runClient`/`runServer` development configurations include the separate `better_spaceflight_probe` mod. They are NOT the final human-playable modpack or production launchers.

After obtaining applicable EULA acceptance and a coordinated runtime slot, start a fresh server and real client in new per-run directories:

```sh
./scripts/gradle-lab.sh runServer -PattemptId=NEW_SERVER_ID
./scripts/gradle-lab.sh runClient -PattemptId=NEW_CLIENT_ID
```

- `/spaceflight_probe status`: checks recorded dimension, identity, hull and block-entity NBT. Does not prove client tracking/rendering or restart merely by printing a message.

If a command fails, preserve the world and full log and inspect the partial state; do not rerun begin, reconstruct a craft, or silently label recovery successful. This probe intentionally does not implement the later crash-transactional coordinator.

Required manual observations still include actual hull/cargo rendering after both handoffs, mounting/camera/interaction correctness, reconnect/restart with exactly one craft and unchanged sentinel inventories, active native physics at altitude, and zero ship gravity/drag in space. The probe presently holds craft static for safe transfer inspection and does not establish these dynamic properties.

## Source boundary

`Vs2411Adapter` contains all current VS internal calls; unsupported versions fail at mod construction. `AssemblyTranslation` uses immutable geometric-center snapshots and exact integral offsets, never COM-world positions. `SectionLayout` guards against index-based chunk copying across incompatible vertical layouts. The native adapter operation is explicitly probe-only, destructive, game-thread-only and not a production transaction.

`src/probe` is not part of the runtime JAR. Do not migrate its operator shortcuts, sentinel items or static anchoring into survival gameplay. Source build provenance identifies uncommitted inputs with a runtime source fingerprint rather than inventing a Git revision.
